自定义评测

在实验室服务器上用 codingBench 评测任意 OpenAI 兼容接口的模型，判题方式与本站相同。模型写的代码会在服务器上执行，所有评测都以无特权用户 bench 运行。

准备

  • 服务器账号：地址、端口和账号向实验室管理员索取，本站不公开。需要 root 或有 sudo 权限的账号（cb 会切换到 bench 用户运行）。
  • 模型接口：OpenAI 兼容的接口地址、模型名和 API key，以及足够的账户余额（费用估算见下文）。

1. 登录

ssh -p <端口> <用户名>@<服务器地址>

2. 设置模型

export MODEL=<模型名>                        # 例如 deepseek-flash
export OPENAI_BASE_URL=https://<平台地址>/v1
read -rsp "API key: " OPENAI_API_KEY && export OPENAI_API_KEY && echo   # 粘贴后回车；不显示，也不进命令历史

3. 冒烟测试

cb livecodebench --smoke      # 只跑最新的几道题，先确认接口、格式和扣费正常

4. 正式运行

export LCB_IDS=samples/lcb_newest35.txt    # 本站结果用的 35 题；全部 100 题用 samples/lcb_newest100.txt
nohup cb livecodebench > ~/lcb.log 2>&1 &   # 断开 SSH 也继续跑
cb progress <模型名>/livecodebench-lcb_newest35-full --watch 30
                       # 已答题数、出错、每个进行中的请求（加 --text 看最新的思考和回答）

推理模型和平台限制较多的模型，在第 4 步前按下面的参数手册加上对应设置，例如：

# 推理模型（思考计入输出 token），例如 DeepSeek-V4.1-Flash / V4-Pro
export MAX_TOKENS=262144 WORKERS=16
export PRICE_IN=0.3 PRICE_HIT=0.006 PRICE_OUT=1.2 PRICE_OFF_IN=0.15 PRICE_OFF_HIT=0.003 PRICE_OFF_OUT=0.6
                       # 单价（美元/百万 token），按平台当前价目填；这里是本站评测时 Flash 的高峰 / 非高峰价

# 平台固定采样参数、思考很长的模型，例如 Kimi K3.1 Pro
export MAX_TOKENS=none LCB_OMIT=temperature,top_p,n,presence_penalty,frequency_penalty \
       WORKERS=4 PRICE_IN=2 PRICE_HIT=0.2 PRICE_OUT=10

5. 结果

生成和判分结束后，cb 自动依次运行：复核判分（cb rejudge，本站的判分方式）、延迟与费用（cb usage）、静态代码质量（cb quality）、代码性能（cb perf）。

cb summary                                          # 所有运行：LCB 自带判分和复核后的分数
cb post <模型名>/livecodebench-lcb_newest35-full    # 跳过了后处理（CB_POST=0）或中途中断时补跑
cb perf <模型A>/<运行> <模型B>/<运行> --out compare.md
                       # 几个模型放在一起交替重测，按相对最快者的倍数对比

运行目录在安装目录的 runs/<模型名>/livecodebench-<清单名>-full/，里面有模型的原始回答、题目清单（problems.json）、每次调用的记录（usage.jsonl）和各项结果：rejudge.jsonl（逐题判分）、usage.md（延迟、首个 token、输出速度、token、费用）、quality.md（静态质量）、perf.md（CPU 时间与峰值内存）。表格都标出方向：↑ 越大越好，↓ 越小越好。比较模型用复核后的分数。

6. 中断与续跑

直接重跑同一条命令：已经答过的题不会再请求；空答案（超时、余额不足、思考用完上限）会重新请求。每次续跑都会在本机重新判分，不花钱。

参数手册

全部通过环境变量设置，在运行 cb 前 export。

变量默认作用怎么选
MODEL必填平台上的模型名，也用作运行目录名（其中的 / 换成 _）按平台文档，如 deepseek-flash、kimi-k3.1-pro
OPENAI_BASE_URL必填OpenAI 兼容接口地址，以 /v1 结尾按平台文档
OPENAI_API_KEY必填平台的 API key用 read -rs 输入，不写进命令行、脚本或仓库
LCB_IDS全部 1055 题只跑清单里的题，每行一个题号；相对路径从安装目录算起samples/lcb_newest100.txt：本站题库 100 题；samples/lcb_newest35.txt：本站结果用的 35 题；也可以自己写清单（题号见“题目”页）
LCB_START不限只跑这个日期之后发布的题，如 2025-01-01设在模型训练截止日期之后，避开可能见过的题；release_v6 的题截至 2025-04-06
LCB_RELEASErelease_v6LiveCodeBench 数据版本保持默认，与本站可比
MAX_TOKENS16384每次回答的最大 token 数，含思考；none 表示不传上限，由平台决定非推理模型用默认；推理模型设成平台允许的最大输出（本站 DeepSeek 262144），或 none。上限太小时困难题会思考到上限、交不出答案而判失败；可以先小后大，续跑只重做空答案
WORKERS16同时发出的请求数按平台限流调；遇到 429 就调小（本站 Flash 16、Pro 8、Kimi 1–4）
STREAM1流式请求：卡住的请求很快重试，记录首个 token 的时间，cb progress 能看到每个进行中的请求保持默认；平台不支持流式时设 0（一次取回整个回答）
LCB_TIMEOUT300 秒流式：两次收到 token 之间的最长间隔；STREAM=0 时为整个回答的超时（默认 1800 秒）保持默认；STREAM=0 时不小于最长思考时间（本站困难题最长约 31 分钟）
LCB_OMIT无请求里不发送的字段，逗号分隔平台固定了采样参数、传了会报错时用，如 Kimi K3.1 Pro：temperature,top_p,n,presence_penalty,frequency_penalty
PRICE_IN、PRICE_HIT、PRICE_OUT不设每百万 token 的单价（输入未命中缓存 / 命中缓存 / 输出，思考算输出），cb usage 用来算费用和每道通过题的费用按平台价目填；分时计价的平台再设 PRICE_OFF_IN、PRICE_OFF_HIT、PRICE_OFF_OUT（非高峰单价）和 PEAK_HOURS_UTC（工作日高峰，默认 DeepSeek 的 1-4,6-10）
CB_POST1跑完自动复核判分、统计延迟与费用、静态质量、代码性能保持默认；设 0 跳过，之后用 cb post 补跑

费用估算

费用 ≈ 输入 token × 输入单价 + 输出 token × 输出单价。输入只有题面，35 题约 2.4 万 token；输出 token 主要是思考，不同模型差别很大。本站 35 题的实际用量：

常见问题

  • 报 400 参数错误：平台不接受某些请求字段，用 LCB_OMIT 去掉。
  • 很多空答案：通常是 MAX_TOKENS 太小，思考用完了上限；调大后重跑同一条命令，只重做空答案。
  • 429 限流：调小 WORKERS。
  • 余额不足：这题记为空答案，之后不再发新请求；充值后重跑同一条命令补齐。
  • 请求长时间没有返回：默认的流式请求超过 5 分钟收不到新 token 就重试；用 cb progress <运行目录> --text 看每个请求是否还在输出、最新在写什么。
  • 其他 benchmark：cb bigcodebench（BigCodeBench-Hard）、cb cruxeval（CRUXEval）、cb all（三个都跑）；本站只用 LiveCodeBench。
