自定义评测

在实验室服务器上用 codingBench 的 cb ladder 评测任意 OpenAI 兼容接口的模型，题目、判题与计分与本站相同。模型写的代码会在服务器上执行，所有评测都以无特权用户 bench 运行。

准备

  • 服务器账号：地址、端口和账号向实验室管理员索取，本站不公开。需要 root 或有 sudo 权限的账号（cb 会切换到 bench 用户运行）。
  • 模型接口：OpenAI 兼容的接口地址、模型名和 API key，以及足够的账户余额（费用估算见下文）。
  • 题目数据已经在服务器上建好；在新机器上复现时，先运行 cb ladder-data 下载官方数据，再运行 cb ladder-build --calibrate 建库并用官方解校验。

1. 登录

ssh -p <端口> <用户名>@<服务器地址>

2. 设置模型

export MODEL=<模型名>                        # 例如 deepseek-flash
export OPENAI_BASE_URL=https://<平台地址>/v1
read -rsp "API key: " OPENAI_API_KEY && export OPENAI_API_KEY && echo   # 粘贴后回车；不显示，也不进命令历史

推理模型和平台限制较多的模型，按下面的参数手册加上对应设置，例如：

# 例如 Kimi K3.1 Pro 的 max（平台固定采样参数）
export REASONING_EFFORT=max LADDER_OMIT=temperature,top_p MAX_TOKENS=1046528 \
       PRICE_IN=2 PRICE_HIT=0.2 PRICE_OUT=10

# 例如 DeepSeek Flash V4.1-1017（分时计价）
export MAX_TOKENS=262144 PRICE_IN=0.3 PRICE_HIT=0.006 PRICE_OUT=1.2 \
       PRICE_OFF_IN=0.15 PRICE_OFF_HIT=0.003 PRICE_OFF_OUT=0.6

3. 冒烟测试

cb ladder --smoke      # 每档只跑第一题、采样 1 次，先确认接口、格式和扣费正常

4. 正式运行

nohup cb ladder > ~/ladder.log 2>&1 &     # 断开 SSH 也继续跑
cb progress <模型名>/ladder-full --watch 30  # 已答的采样、出错、每个进行中的请求
cb ladder --tiers L4,L5                     # 只跑部分档位；--only usaco-1452,fcs-85 只跑指定的题

5. 结果

生成结束后，cb 自动依次判题、复测运行效率、拟合复杂度、统计静态质量并写报告。运行目录在安装目录的 runs/<模型名>/ladder-full/，报告在其中的 report/report.md。

cb ladder-post <模型名>/ladder-full                      # 跳过了后处理（CB_POST=0）或中途中断时补跑
cb ladder-report <模型A>/ladder-full <模型B>/ladder-full --out <目录>
                       # 几个模型放在一份报告里对比

6. 中断与续跑

直接重跑同一条命令：已经答过的采样不会再请求，判题在本机进行，不花钱。

参数手册

全部通过环境变量设置，在运行 cb 前 export。

变量默认作用怎么选
MODEL必填平台上的模型名，也用作运行目录名（其中的 / 换成 _）按平台文档，如 deepseek-flash、kimi-k3.1-pro
OPENAI_BASE_URL必填OpenAI 兼容接口地址，以 /v1 结尾按平台文档
OPENAI_API_KEY必填平台的 API key用 read -rs 输入，不写进命令行、脚本或仓库
REASONING_EFFORT不传请求里的 reasoning_effort，如 low、high、max不设即 auto，由接口采用默认值；要比较思考强度时每档各跑一次
LADDER_NL1=1,L2=1,L3=3,L4=3,L5=1每档每题的采样次数保持默认，与本站可比
MAX_TOKENS不传每次回答的最大 token 数，含思考推理模型设成平台允许的最大输出，或保持不传，由平台决定
WORKERS16同时发出的请求数按平台限流调；遇到 429 就调小
STREAM1流式请求，记录首个 token 的时间与输出速度保持默认；平台不支持流式时设 0
LADDER_TIMEOUT300 秒流式：两次收到 token 之间的最长间隔；STREAM=0 时为整个回答的超时（默认 1800 秒）保持默认
TEMPERATURE0.2采样温度（LiveCodeBench 的设置）平台固定采样参数时用 LADDER_OMIT 去掉
LADDER_OMIT无请求里不发送的字段，逗号分隔如 Kimi K3.1 Pro：temperature,top_p
PRICE_IN、PRICE_HIT、PRICE_OUT不设每百万 token 的单价（输入未命中缓存 / 命中缓存 / 输出，思考算输出），用来算费用和每份解出答案的费用按平台价目填；分时计价的平台再设 PRICE_OFF_IN、PRICE_OFF_HIT、PRICE_OFF_OUT（非高峰单价）和 PEAK_HOURS_UTC
CB_POST1生成结束后自动判题、复测性能、拟合复杂度、统计静态质量并写报告保持默认；设 0 跳过，之后用 cb ladder-post 补跑

固定不变的设置

项目固定为
题单samples/ladder.json：本站的 112 题
提示词USACO、EGOI 沿用 LiveCodeBench 的写法；FrontierCS 用其官方提示词（见 原理 › 提示词）
判题官方时限、官方测试数据与 checker，按来源的官方规则计分
运行效率与复杂度与官方解在同一台机器上交替运行比较
静态代码质量L1、L2 的 Python 答案：Pylint 3.3.5、Radon 6.0.1

费用估算

费用 ≈ 输入 token × 输入单价 + 输出 token × 输出单价。输入只有题面，输出 token 主要是思考，不同模型差别很大。本站全部 202 个采样的实际用量：

模型输出 token费用（美元）
Kimi4.97M$50.12
DeepSeek8.33M$5.79
MiniMax10.46M$6.30

常见问题

  • 报 400 参数错误：平台不接受某些请求字段，用 LADDER_OMIT 去掉。
  • 429 限流：调小 WORKERS。
  • 余额不足：运行暂停，已答的采样保留；充值后重跑同一条命令补齐。
  • 其他 benchmark：cb livecodebench（LiveCodeBench，见 上一版评测）、cb bigcodebench、cb cruxeval。
